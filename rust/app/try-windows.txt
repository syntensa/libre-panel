Libre Panel in Rust: a first build to try
=========================================

This folder is Libre Panel written anew in Rust (docs/RUST.md), as far as it is: one program,
libre-panel.exe, with no Python in it. It is not the Libre Panel you installed and changes
nothing of it: it only reads your config.toml and writes no file but a PNG you name.

It shows a theme on ONE panel: the first one of config.toml ([device]). A TURZX USB panel is
driven through Libre Panel's engine (tools\libre-panel-engine.exe), with the same commands
the installed app sends: video where [video] says so, single pictures otherwise.

To try it
---------
1. Quit Libre Panel (its tray icon, Quit) and the TURZX app: only one program can have the
   panel.
2. Open a terminal (PowerShell) in this folder.
3. .\libre-panel.exe config
   says which config.toml it reads (yours: %APPDATA%\LibrePanel\config.toml) and what it
   found in it. A mistake in it is said here.
4. .\libre-panel.exe render --output frame.png
   draws one frame of your theme into frame.png. No panel is touched.
5. .\libre-panel.exe sensors
   lists the readings it has, with their keys. With Libre Panel's sensor service set up
   (Unlock all sensors in the installed app) the temperatures, the power, the fans and the
   graphics card are among them; .\libre-panel.exe sensors --check-service says whether
   the service answers.
6. .\libre-panel.exe run
   shows the theme on the panel until Ctrl+C. What it says in the terminal is worth
   copying if something is wrong.

   .\libre-panel.exe run --theme terra      another theme, without changing config.toml
   .\libre-panel.exe run --demo             readings made up instead of the PC's

What to look at
---------------
- Does the panel show the theme, the right way up, in its colours?
- Does it move smoothly (seconds, graphs, bars)?
- Processor load and memory of libre-panel.exe and libre-panel-engine.exe in Task Manager,
  beside the installed app's with the same theme.
- After Ctrl+C: does the installed Libre Panel start as before?

What it does not do yet
-----------------------
- Readings: what Windows itself tells (the processor's and the graphics card's load, every
  core, the clock, memory, drives, network with its link, the programs that use the most,
  ping, battery, uptime, the volume) and what LibreHardwareMonitor reads through Libre
  Panel's sensor service (or its own web server): temperatures, power, fans, the graphics
  card; and a game's frame rate through PresentMon (tools\PresentMon.exe), which needs
  administrator rights or the "Performance Log Users" group. Music, weather and the AI
  activity are missing: their places stay empty. Which program is the game is not found
  yet: the one that shows the most frames counts.
- One panel; no pages (game, music), no notices, no transitions between themes, no videos
  in themes, no app window and no tray icon.
- Panels other than TURZX USB and the Hongtai family: config.toml's `driver = "virtual"`
  writes the frames into a PNG file.
